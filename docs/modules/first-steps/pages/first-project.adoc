= Iteración 1 - Login

Desde ahora hasta el final de la asignatura vamos a desarrollar un proyecto sobre el que aplicar las herramientas y métodos que vamos introduciendo durante el curso.

El proyecto tendrá un *login* y *registro de usuario*, así que vamos a comenzar por implementar esta funcionalidad.

== Requisitos

=== Requisitos no funcionales comunes

* *Aplicación Web*: debe poder ejecutarse correctamente en los navegadores más utilizados (Chrome, Firefox, Edge, Safari) en sus últimas versiones.
* *Opcional*: diseño responsive (adaptable a distintos dispositivos móviles / PC).
* Usar por el equipo de desarrollo una *herramienta de control de versiones* (a elegir):
** GitLab (en la máquina Azure del equipo)
** *GitHub* (en GitHub.com con repositorio *privado* en la organización del equipo) _(recomendado)_
* *Tecnología de implementación*: tenéis libertad para elegir el lenguaje o tecnología para implementar el proyecto. En principio, Java (Spring Boot) y JavaScript/TypeScript (Node.js, React, Angular, Vue) son válidas. También podéis elegir otros lenguajes o frameworks: .Net, Python (Django/FastAPI), etc.

=== Requisitos funcionales comunes

==== Autenticación y registro de usuarios (login)

La aplicación debe cumplir las siguientes funcionalidades:

* Permitir el *registro de nuevos usuarios*.
* Permitir que el usuario registrado pueda hacer *login* (usuario/contraseña).
* Se definen dos tipos de usuarios o *roles*: administrador y usuario (normal).

El *usuario administrador* podrá:

* Listar todos los usuarios registrados en el sistema.
* Crear un usuario (asignando el rol de administrador o de usuario).
* Modificar los datos de usuarios.
* Eliminar usuarios.

El *usuario normal* podrá, una vez logueado:

* Modificar sus datos de perfil (email y contraseña).

Un usuario logueado puede hacer *logout*.

==== Requisitos funcionales específicos

El objetivo será elegir un proyecto e ir completándolo, implementando funcionalidades basadas en la especificación de requisitos, modelado, diseño, implementación, pruebas, despliegue, etc.

Se planteará una metodología basada en varias iteraciones hasta final de curso. En una segunda iteración cada equipo propondrá nuevas características (features) para incorporar a su proyecto.

== Entregables

Se piden las siguientes tareas:

. *Crear un nuevo repositorio GitHub privado* para el proyecto e invitar al profesor.

- ejecución de las pruebas unitarias.
- cálculo de la cobertura de código de las pruebas unitarias.

== Despliegue en Azure

La aplicación debe ser desplegada en Azure, bien usando una máquina virtual o bien usando webapps. Se recomienda utilizar los recursos gratuitos de Azure, en concreto para la base de datos.

Una vez desplegada la aplicación en Azure, se deben *clonar los tests de Selenium* y cambiarlos para que prueben la aplicación funcionando en Azure (cambiando simplemente la URL base de `localhost` a la URL de la webapp).
